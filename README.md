# Deadlock Family

Демонстрационный интернет-магазин по ТЗ `Deadlock_Family_MVP_TZ_v1`: Nuxt 3, Vue 3, TypeScript, Tailwind CSS, Pinia, Nitro Mock API. Интерфейс — русский, демонстрационная валюта — RUB, цены API в копейках. Основные категории строго фиксированы: Одежда, Брелки, Фигурки, Сувениры. Персонажи и темы относятся к коллекциям и тегам.

## Запуск

Требуется Node.js 22.12+ (проверено на Node 24) и npm. Из каталога `store`:

```sh
npm ci
npm run dev
```

Открыть http://127.0.0.1:3000. Админ-панель: http://127.0.0.1:3000/admin. Она намеренно отсутствует в покупательской навигации. В Windows PowerShell с запретом `.ps1` используйте `npm.cmd` вместо `npm`.

```sh
npm run typecheck
npm test
npx playwright install chromium
# При работающем dev-сервере на порту 3000:
npm run test:e2e
npm run build
npm run preview
```

`npm run build` создаёт самостоятельный Node-сервер в `.output/`. Для развёртывания скопировать `.output/` на сервер и запустить `node .output/server/index.mjs` с переменными `HOST`, `PORT`, при необходимости за HTTPS reverse proxy. Полностью статическая публикация не поддерживает Mock API и не подходит.

`npm run build:cloudflare` отдельно собирает Nitro Cloudflare Worker и готовит `dist/server/index.js`, `dist/client/`, `dist/.openai/hosting.json` для приватной демонстрации в Sites. Это дополнительная цель сборки, не замена Node-развёртыванию.

## Что реализовано

- Главная с отдельным архивным фоном и адаптивным интерфейсом, новинками, коллекциями и рекомендуемыми товарами. Изображения оптимизированы в WebP, для телефона предусмотрен облегчённый фон. Фотообласти мерча извлечены из предоставленного концепта. Оригинальная демо-фигурка создана image_gen; сведения в `docs/assets.md`.
- Каталог, четыре категории, коллекции, поиск по названию/описанию/тегам, доступность, сортировка по цене/новизне, пагинация. Параметры сохраняются в URL. Новинка — опубликованный товар с датой первой публикации за последние 30 дней.
- Товар, изображения, размеры/цвета, SKU, остаток и цена варианта. Недоступный вариант нельзя добавить в корзину.
- Pinia-корзина с localStorage: одинаковые варианты объединяются, разные размеры остаются отдельными. Суммы и доступность заново проверяются Mock API. Изменённые цены нужно явно принять, недоступные позиции удалить или уменьшить количество.
- Тестовое оформление с заранее заполненными вымышленными данными, двумя фиксированными способами доставки (0/350 ₽), валидацией, подтверждением и номером заказа. Сервер пересчитывает цены и остатки, создаёт `demo_created` и уменьшает демонстрационные остатки.
- Админ-панель: поиск и статусы, создание/редактирование, черновик/публикация/скрытие/архивирование, удаление с подтверждением, SKU/цены/остатки, готовые изображения или локальный PNG/JPEG/WebP до 1 МБ. Флаг Featured управляет блоком рекомендуемых товаров на главной.
- Редактор коллекций: название, slug, описание, обложка, включение в главную и назначение товаров. Тестовые заказы: состав, сумма, дата, статусы `demo_created`, `demo_processing`, `demo_completed`, `demo_cancelled`.
- Страницы 404, состояния загрузки/ошибки/пустой выдачи, повтор запроса, мобильное меню, клавиатурный фокус, модальное подтверждение с удержанием фокуса и Escape, reduced motion, SEO и noindex для административных/служебных страниц.

## Демо-сессия и сброс

Nitro хранит данные в памяти процесса, раздельно для случайного HttpOnly cookie `df_demo` (SameSite=Lax, 24 часа). Сессии ограничены по количеству; перезапуск сервера, сборка, вытеснение или смена edge-изолята сбрасывают изменения. Между браузерами синхронизации нет. Для последовательной проверки сценариев предпочтителен один Node-процесс. Edge-публикация предназначена для просмотра и кратких демо-сессий, не гарантирует сохранение памяти между запросами.

В `/admin` есть кнопка «Сбросить демо-данные» с подтверждением. Она восстанавливает исходный каталог/коллекции, удаляет тестовые заказы и очищает корзину браузера. API: `POST /api/v1/demo/reset` (с cookie той же сессии). Сама корзина хранится только в localStorage устройства, без контактов.

Проверка ошибок: `/shop?scenario=400`, `?scenario=404`, `?scenario=500`, `?scenario=empty`. Стандартные ответы API: `{ "error": { "code": "...", "message": "..." } }`. Контролируемые ошибки доступны также через параметр `scenario` у остальных методов. Опции для проверки есть в обзоре админ-панели.

## Контракт и будущий backend

`shared/types.ts` — явные модели `Product`, `ProductVariant`, `Category`, `Collection`, `CartItem`, `Order`, `OrderItem` и статусы. `composables/useApi.ts` — единый типизированный слой запросов. Шаблоны не импортируют seed или серверные mock-обработчики. `server/utils/domain.ts` — проверяемая серверная валидация и правила; `server/api/v1/[...path].ts` — HTTP-адаптер.

`docs/openapi.json` — OpenAPI 3.0.3: схемы, методы, HTTP-коды, примеры JSON-ответов и ошибок. Обновление: `node scripts/generate-openapi.mjs`. Список контрактов включает товары, категории, коллекции, корзинный quote, тестовые заказы, административные операции и reset.

Для Spring Boot задайте `NUXT_PUBLIC_API_BASE` (пример в `.env.example`), сохраните контракты и структуру ответов. Рекомендуется same-origin reverse proxy `/api/v1` к Spring, чтобы не менять компоненты и избежать дополнительной CORS-настройки. Затем замените demo-cookie полноценной серверной сессией, добавьте серверные роли, CSRF, ограничения запросов и журналирование. Каталог переносится в PostgreSQL, файлы — в объектное хранилище. Цена `expectedPrice` служит только подтверждением изменений: backend всегда берёт текущую цену из собственного каталога. Платёжный checkout и подтверждение провайдера должны реализовываться отдельно на сервере.

## Проверка

Unit-тесты проверяют поиск/фильтры/сортировку/пагинацию, объединение вариантов, остатки, изменение цен, пересчёт заказа, отсутствие контактов в заказах, публикацию/скрытие, SKU, обязательность изображения и состав коллекций. Playwright проверяет непрерывные сценарии покупателя и администратора, перезагрузку корзины, изоляцию сессий, ошибки/404 и отсутствие горизонтального переполнения при 360/768/1440 px. Скриншоты находятся в игнорируемом `test-results/`.

## Ограничения

Это MVP для проверки интерфейса, не коммерческая система. Нет настоящей регистрации, авторизации админ-методов, базы данных, оплаты, внешней доставки, аналитики или реальных заказов. Не вводите настоящие контактные данные: форма предназначена только для вымышленных значений; введённые контакты проверяются и сразу отбрасываются сервером, не входят в объекты заказов. Локально выбранные изображения также непостоянны.

Фото, цены, названия, характеристики и способы доставки демонстрационные. Окончательные товары, логотип, официальные социальные ссылки и права на коммерческое использование согласуются отдельно. До запуска продаж нужны отдельная backend-реализация, серверная защита, платёжные/логистические интеграции и подготовленные условия обработки персональных данных.
